# 🏗️ IMPLEMENTASI PRINSIP OOP DALAM KODE

## 1. ABSTRAKSI (Abstraction)

Definisi: Menyembunyikan kompleksitas internal dan hanya menampilkan yang perlu diketahui user.

Contoh dalam kode:

a) Fungsi get_db()
- User tidak perlu tahu detail koneksi MySQL
- Cukup panggil get_db() dan terima connection object

b) bcrypt untuk Password Hashing
- Algoritma hashing yang kompleks disembunyikan
- User hanya panggil hashpw() & checkpw()

c) Decorator @login_required_pelanggan
- Logik validasi login disembunyikan di decorator
- Route hanya perlu add @login_required_pelanggan

---

## 2. ENKAPSULASI (Encapsulation)

Definisi: Menggabungkan data & method yang berkaitan dalam satu unit (fungsi/class) dan membatasi akses dari luar.

Contoh dalam kode:

a) Database Credentials
- Credentials disimpan di environment variables
- Tidak hardcoded di code (aman)
- Hanya `get_db()` yang akses db_config

b) Session Data
- Data user disimpan dalam session (server-side)
- Tidak di-expose ke client
- Hanya accessible melalui session dictionary

c) File Upload Handling
- Logic file handling (sanitasi, path, naming) dikapsulasi
- Mencegah directory traversal attacks

---

## 3. POLIMORFISME (Polymorphism)

Definisi: Kemampuan satu interface untuk merepresentasikan berbagai tipe data atau behavior.

Contoh dalam kode:

a) Login Endpoint Menangani 2 Tipe User
- Satu route `/login` handle 2 tipe user (admin & pelanggan)
- Behavior berbeda tergantung tipe user

b) Decorator Digunakan untuk Berbagai Route
- Decorator yang sama digunakan di berbagai route
- Behavior berbeda tergantung context

---

## 4. INHERITANCE (Warisan)

Definisi: Mewarisi property & method dari class/object lain.

Catatan: Kode ini tidak menggunakan class secara ekstensif (Python functional style), tapi ada beberapa pattern inheritance-like:

a) Flask App Inheritance
- `app` adalah instance dari Flask class
- Inherit semua method Flask: route(), run(), etc.

b) Exception Handling Inheritance
- `mysql.connector.Error` adalah subclass dari `Exception`
- Polymorph: catch specific error lebih dulu, baru generic

---

## 5. KOMPOSISI (Composition)

Definisi: Membentuk object kompleks dari object yang lebih sederhana.

Contoh dalam kode:

a) Join Query (Komposisi Data)
- Data tiket & pelanggan dikomposisi dalam satu query result
- Relationship: tiket punya user_id yang link ke pelanggan

b) Nested Data Structures
- List of dictionaries = komposisi data primitif
- Masing-masing destinasi adalah kombinasi dari field yang berbeda

---

## 6. SINGLE RESPONSIBILITY PRINCIPLE (SRP)

Definisi: Setiap function/module punya satu tanggung jawab utama.

Contoh dalam kode:

| Function | Tanggung Jawab |
|----------|---|
| get_db() | Buat koneksi database |
| test_connection() | Test koneksi database |
| init_database() | Inisialisasi/buat tabel database |
| login() | Handle login logic |
| register() | Handle register logic |
| checkout() | Handle pembelian tiket |
| upload_bukti() | Handle upload file |
| kontak() | Handle form kontak & kirim email |

Setiap function fokus pada satu hal saja → mudah maintain & test.

---

## 7. DRY PRINCIPLE (Don't Repeat Yourself)

Definisi: Jangan repeat kode yang sama di multiple tempat.

Contoh dalam kode:

a) Reusable Database Query
- Digunakan di ratusan tempat dalam file
- Jika perlu ubah config, cukup ubah satu tempat

b) Reusable Decorator
- Digunakan di multiple routes
- Tidak perlu repeat cek login logic di setiap route

## RINGKASAN IMPLEMENTASI OOP

| Prinsip OOP | Aplikasi dalam Kode | Manfaat |
|---|---|---|
| Abstraksi | get_db(), bcrypt hashing, decorators | Hide complexity, easier to use |
| Enkapsulasi | Session variables, db_config, file upload | Secure, controlled access |
| Polimorfisme | Login handle 2 user type, decorator di multiple routes | Reusable, flexible |
| Komposisi | JOIN queries, nested data structures | Combine simple objects into complex |
| SRP | Setiap function 1 responsibility | Easy maintain, test, debug |
| DRY | get_db(), decorator reusable | Less code duplication |
